# Dependency-scoped qualification

The first Linux run is `BOOTSTRAP_SCOPED_LINUX`: all 739 targets are FRESH. There are no accepted Linux GSS objects in this candidate. Windows success and official Mathlib cache downloads are separate evidence and do not qualify Annex modules on Linux.

The partition is 57 common Annex providers, seven existing GSS slices (328 modules), 347 other Annex modules, and the root plus six Project entries (7). No target or required check is removed. All stages remain sequential. The final stage restores the full 732-library environment and retains independent root/entry imports, the pinned Project parser, all module-origin declarations/types/axioms, 3252 public names, and cleanliness.

`provider-graph.json` records source-bound imports parsed by the pinned Lean header parser, including implicit Init, public/meta imports, tactics and plugins. Each stage's explicit roots select the official fixed Mathlib cache closure. An empty root list performs no acquisition; there is no full-cache fallback. Acquisition uses batches of 12 roots, retains shared compressed objects between batches, and limits their total to 384 MiB. Expanded objects, sidecars, IR and official native/plugin artifacts are retained. Compressed archives are removed only after the exact requested expanded inventory is verified. A real native import of the selected external roots precedes Annex compilation.

The 25 disjoint output bundles group modules by identical downstream consumers. Each compiled object is uploaded once, then only actual consumers download it. Small stage/identity/budget receipts are separate from compiled objects and full logs. Hash-verified same-filesystem moves avoid duplicate restored/output copies. Final integration necessarily needs all 732 libraries; its peak is accounted separately, not described as free.

Resource policy keeps the 4 GiB disk floor and RSS/time monitors. Per-stage output and provider bounds are based on measured Windows reference objects with explicit headroom; they are not measured Linux sizes. Runtime admission records actual free space and required incremental/temporary bytes. Every upload uses actual sizes and conservative ZIP bounds under the inherited 1.5 GB policy cap. This cap does not establish the account's free storage entitlement or spending-stop settings. The ten native jobs have 330-minute timeouts and the failure reporter has five minutes. Three-day retention is checked against actual expiry before download and does not guarantee unbounded queue time.

Each native job has a separate <=128 KiB diagnostic path, and the no-setup failure reporter reserves <=1 MiB. These reservations are deducted from the shared cap. Neither path needs the build disk floor, Lean, or prior artifacts. Missing/failed/skipped required stages remain FAIL. The heavy final job runs only after all predecessors succeed.

## Qualified deltas after an accepted Linux run

`qualification-catalog.json` is emitted only after all final gates pass. It records exact module keys, compiler binary/platform/architecture, source/flags/provider/import identities, real output hashes, declaration/type/axiom digests, producer and FRESH/INHERITED counts. Archive this small catalog together with its exact qualification receipt in the existing private repository through a separately authorized acceptance step before cache expiry. Three-day artifacts are disposable accelerators, not the sole permanent proof record.

`accepted-linux-reuse.json` is intentionally empty here. A later accepted catalog can populate it with explicit owner-accepted Linux producer records and module records. The producer run must be exact and completed/successful. The consumer rechecks current keys and every output byte. Exact task-local objects or explicitly approved per-module GitHub artifact locators can supply the cache; missing/expired cache is `CACHE_MISS` and rebuilds only required modules. The current consumer-partition artifacts may be repackaged into exact module caches by an authorized later worker; there is no automatic claim that such caches already exist.

Source/provider/compiler/platform/flags/import changes invalidate the affected modules and their reverse dependencies. Unrelated workflow/document/commit changes do not invalidate mathematical keys, but the current candidate/workflow identity is always checked. Partial compile success is not accepted slice qualification. This implementation conservatively requires a completed successful producer qualification before inheritance. Whole-run FAIL artifacts are not accepted automatically.

The final census, whole-target accounting and independent integration checks remain mandatory in qualified-delta mode. INHERITED is never reported as fresh compilation. Evicted cache objects do not erase archived qualification evidence; unavailable objects are regenerated for the required scope. No workflow dispatch, rerun, cancellation, publication, billing change, paid runner, new service or permission change is performed by these helpers.
